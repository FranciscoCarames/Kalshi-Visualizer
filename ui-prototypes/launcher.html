KALSHI · TERMINAL PRO · FRAMEWORK BAKE-OFF

Five builds, one slice, measured for no-lag

Same Terminal Pro Opportunity surface, same dataset, same synthetic stress stream, same standardized grid (AG Grid; Glide for the canvas variant), same perf overlay. Open each, hit the stress presets in the bottom-right overlay (rows × updates/sec), and compare FPS + apply-latency. Each has a read-only NO ORDERS ladder and the gross/not-riskless disclaimer.

How to judge: in each app's PERF overlay (bottom-right), click 10k rows then 240 updates/sec. Watch sustained fps (green ≥55) and apply p95 (ms). Lower latency + steadier fps = less lag. Also feel scroll + row-select under load.
Run: from ui-prototypes/ run npm install once, then a dev server per app (npm run dev:react, dev:solid, dev:svelte, dev:vue, dev:canvas). Ports are fixed below. "real (poll)" source needs a separate serve.py on :8000 (read-only). Throwaway evaluation prototypes — branch feat/ui-prototype-bakeoff, never main.
