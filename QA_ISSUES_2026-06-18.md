## OPEN defects (the real work-list)

### High
- [ ] **H1 🔴 — ALERTS surface downloads ~28.7 MB / ~14 s.** `GET /backlog/events?days=7` returns every event
  from the last 7 days, unbounded, over the **1.84 GB** `snapshots.db` → 28.7 MB JSON, 13.8 s, big DOM. Default
  `/backlog` is fine (36 KB, 1.7 s). **Why it matters:** a 14 s blocking load on a casually-clicked surface;
  worsens as the DB grows. **Fix:** cap/paginate (top-N or cursor) or aggregate server-side; lazy-load the
  surface; run `compact_store.py` to shrink the DB.
- [ ] **H2 🔴 — Partial, volatile coverage (429 lottery).** ~39–66 of ~158 series HTTP-429 per scan, so each
  snapshot covers a *different* partial subset (actionable count swung 2→3→11; NHL/Golf appear then vanish).
  Surfaced in OPS, but the headline count reads as "the market" when it's "what scanned." **Fix:** a
  "coverage N%" badge by the count; tune concurrency / honor `Retry-After` / spread series across scans.

### Medium
- [ ] **M2 🔴 — Banned word "locked gross" in the Inspector best-case.** Project bans "locked/riskless/true
  arbitrage" (gross, top-of-book ≠ guaranteed). **Fix:** approved phrasing, single-sourced from `glossary.py`.
  *(Quick win.)*
- [ ] **M3 🔴 — Default bands silently zero whole categories.** A section's default band (e.g. bounded-loss
  max-loss 5¢) can hide every in-scope row, so the tile shows "0" → reads as "empty" when it's just filtered.
  **Fix:** show "0 (filtered)" vs true 0, soften/widen the default band, or surface the pre-band count.
- [ ] **M4 🔴 — "Payout÷cost 33×" framing on cheap-NO longshots** invites lottery-ticket misreading (a big
  multiple just reflects a low-probability payout, not an edge). **Fix:** demote it below Breakeven % / Max loss ¢.
- [ ] **N1 🔴 — First workspace column has no min-width floor.** Drag handler clamps the M/R columns to
  `[60,1000]px` (`Workspace.tsx:179`) but the first column is `1fr` with no floor → dragging the first vertical
  splitter fully left collapses Scanner+Inspector to ~2px (lost until RESET). **Fix:** `min-width` on the first
  column (or clamp it like the others). *(new in pass 2)*
- [ ] **N2 🔴 — Client CSV mis-scales the cents columns.** `csv.ts` dumps raw values without the column `fmt`,
  so `Est. net edge $` and `Est. fees $` (`"cmoney"` = cents) export as un-scaled integers under `$` headers
  (`842` = $8.42), mixed with true-dollar columns (`Max gross profit`, `Est. net max profit`) in the same file.
  Affects **both ⬇ CSV and Export-selected** (shared code). The server **ZIP** CSV is fine (explicit
  `_c`/`_dollars` suffixes). **Why it matters:** 100× silent error in the numbers most likely to be acted on.
  **Fix:** apply the column `fmt` (or /100 the cmoney cols) in `csv.ts`. *(new in pass 2; reconfirmed pass 3)*

### Low
- [ ] **N3 ⚪🔴 — CompareView ignores the staleness gate.** Scanner/inspector flip `Tradable` to "No — stale"
  once the snapshot ages; CompareView prints raw "Yes" → same opp can disagree across views. **Fix:** apply the
  staleness check in CompareView. *(new in pass 2)*
- [ ] **L1 🔴 — Empty-state copy blames the wrong filter.** Says "section / band filters" even when the **fee**
  filter hid the rows. **Fix:** name the filter that actually emptied the view.
- [ ] **L2 🔴 — Lenses not scoped per section.** RIPENESS / SETUP QUALITY (containment concepts) are offered on
  cheap-NO outright rows. **Fix:** scope the lens menu to the active section.
- [ ] **L3 🔴 — Row click drops URL query params** (`?…section=act` → `/`), losing shareable state. **Fix:**
  preserve the query string on selection.
- [ ] **L4 🔴 — ALRT badge vs ALERTS list mismatch** when fee-negative rows are hidden (badge and list count
  different sets). **Fix:** compute the badge from the same filtered set the panel renders.
- [ ] **Low note 🔴 — unknown ticker returns empty book as `ok:true`** — `…/orderbook?ticker=BOGUS` →
  `200 {yes:[],no:[],ok:true}`, indistinguishable from a genuinely empty book. Graceful but ambiguous.
  **Fix (optional):** flag ticker-not-found distinctly.

## RESOLVED / DOWNGRADED (investigated — no longer action items)

- **C2 ⬇️ — "Fractional contract sizes."** The live Kalshi API returns sizes fractional *itself*
  (`KXNBA-27-ATL yes_bid_size_fp="872.46"`, `KXNASCARRACE-NAV26-ANPE "89.58"`); `data.py:747 to_float()` is
  faithful — `*_fp` is a decimal string, **not** a ×10⁸ fixed-point int. **Not a bug.** Optional only: round/floor
  for display, and note the trade-card size (market `*_size_fp`) vs depth-ladder size (`/orderbook`) are two
  Kalshi feeds that can disagree.
- **M1 ✅ — "401 /auth/preferences, no persistence."** A **no-auth-mode artifact only.** Under `AUTH_ENABLED=1`
  the per-user profile persists in `auth.db` and restores on login (verified `theme=hc` / `textSize=large`
  round-tripped + survived re-login). The 401s are expected when auth is off.

## NOT defects — verified-correct or environment/tooling limits

- **Engine math correct, price-verified 3 ways** (SPA = Kalshi API = Kalshi website): dutch-book floor/edge,
  Buy-NO = `no_ask`, sizes mirror `*_size_fp`, fee model `0.07·c·p·(1−p)` per-leg round-up, depth ladder vs raw
  `/orderbook`, containment shape parent ≥ child. Boston vs Seattle: 55¢+44¢=99¢ → +1¢, units 3 — exact.
- **Dark detectors validated by 255 passing unit tests** (containment cross / field over-underround / synthetic
  bundle) — they have no live instances right now but are test-covered.
- **Crossed/one-sided books** handled by `data.py:358 quote_quality` and deliberately **excluded from
  opportunities** (so a live crossed *opportunity* is not expected — that exclusion is the honest behavior).
- **Panel-relocate drag-and-drop** — code-verified (`.ph draggable` → `.dropslot` → `move()`) but
  un-automatable (HTML5 native DnD won't fire via the extension, JS dispatch, or Playwright). Not a product bug;
  column-reorder DnD (same family) works for a real user.
- **Live WS overlay (Stage 2A–2D)** — correctly gated off; needs an RSA Kalshi key (no creds → not testable).
- **Mobile** — no dedicated breakpoint (window floors ~509px, reflows to a scrollable desktop-terminal layout).
  A limitation to note, not a defect.
